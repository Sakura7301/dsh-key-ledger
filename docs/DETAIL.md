# 钥匙簿（Credential vault）

把这一台 DSH 里**散落各处的密钥与凭据**收拢成一处总账，看清每条凭据的来历、
被谁用过，并且可以就地查看、修改、删除。

## 它解决什么

密钥在 DSH 里通常同时存在于四五个地方，彼此不知道对方：

| 位置 | 例子 |
|---|---|
| credential store（`~/.dsh/.credentials.yaml`） | `refs` 里的 `DEEPSEEK_API_KEY`；`records` 里的 `llm-pi-ai/openai-codex` 授权 |
| 启动环境 / `.env` | `DEEPSEEK_API_KEY=… dsh`，或项目里的 `.env` |
| 插件自己的文件 | `~/.dsh/openai-gateway/api-key`、`~/.dsh/ssh/id_ed25519`、`~/.dsh/certs/*.pem` |
| JSON 账号存储 | 微信 bot 的 `state.json`、B 站 cookie 的 `bili_credential.json` |
| 配置里写死的字面量 | `cordis.patch.yml` 里的 `apiKey: sk-…`（危险） |

这个插件把这五类都找出来，统一列出：类型、来源、掩码值、使用方、访问记录。
**它不复制秘密** —— 值永远留在原来的权威位置，插件只持久化登记信息、备注、
标签、访问日志和引用索引。所以不会出现「两份值各说各话」，也不会多出一个泄漏面。

## 界面

**设置 → 钥匙簿**。

- 顶部：条目统计、引用索引时间、搜索框、按类型筛选、`重建引用索引`、`新增凭据`。
- 列表：类型圆点、凭据名、显示名、掩码值、来源路径、使用方计数。
- 点开一行看四块：
  - **凭据值**：默认只有掩码；点「显示」才向宿主取明文，60 秒后自动收回，每次显示都记访问日志。
  - **谁来用它**：配置引用（`file:line`）、插件包、技能、**用过的会话**（只显示会话名称 + 出现次数，按最近活跃排序；名称取会话记录里的标题）。
  - **访问记录**：经本保险库的取用/修改/删除，带时间、调用者、理由。
  - **注记**：显示名、标签、备注、置顶。备注按「这是什么 / 谁在用 / 删了会怎样 / 怎么换」四件事写，不给术语。
- **移出列表 / 恢复**：删不掉的类型（启动环境变量、明文配置）不会硬删，改成移出列表，随时可恢复。

### 使用统计怎么读

每条凭据都显示：**最近一次使用**、**平均频率**、近 7 / 30 天次数、以及会话引用次数与最近引用时间。
两种「使用」在界面上分得很清楚：

- **取用（经本保险库）**：真实调用，有调用者与理由可审计，平均频率按它的间隔算；
- **会话引用**：会话记录里出现过这个标识 —— 只是痕迹，不等于调用。

### 能改什么、不能改什么

| 类型 | 改 | 删 |
|---|---|---|
| `ref`（credential store 的键） | 可以，写回 store，下一个请求即生效，不用重启 | 可以（`unset`） |
| `record`（`<owner>/<id>` 授权记录） | 由宿主插件解释，这里只读 | 可以 |
| `env`（启动环境变量） | 只读 —— 它是启动快照 | **删不掉**（不是本插件存的）；可「移出列表」不再显示 |
| `.env` 文件里的项 | 只读（不代写） | **可以删**：删掉那一行并留 `.bak` 备份 |
| 文件型（私钥 / 证书 / api-key 文件） | 可以替换内容，改前自动留 `.bak-时间戳` | 可以，同样先备份 |
| JSON 字段（token / cookie） | 可以改该字段，改前备份整个文件 | 可以删该字段，先备份 |
| 明文配置 | 只读，标红提示 | **不代删**（改 profile 配置有风险）；建议收归仓储 + 手改引用名，或「移出列表」 |

## agent 怎么取密钥

工具 `vault`：

```
vault { action: "list" }                              # 看有哪些（只给掩码）
vault { action: "describe", name: "DEEPSEEK_API_KEY" } # 看它被谁用
vault { action: "get", name: "DEEPSEEK_API_KEY", reason: "调用 DeepSeek 接口" }
vault { action: "set", name: "MY_KEY", value: "…" }    # 新增或修改
vault { action: "delete", name: "MY_KEY", confirm: true }
vault { action: "scan" }                               # 重建引用索引
```

插件还会注册一条常驻的系统提示纪律：**任何需要密钥的行为都必须走 `vault` 取用**，
禁止直接读凭据文件、`echo` 环境变量、把密钥写进配置或源码。这条纪律对每个会话、
每个子代理都生效，不依赖模型记住上下文。

## 引用索引的边界（如实说明）

- **插件/技能/配置引用**：在包源码、技能文档、`cordis.patch.yml` 里搜到该凭据标识，
  给出 `file:line`。这是静态依赖证据，准确。
- **会话**：把会话记录（zstd 压缩的 JSONL）解压后搜标识串。**它说明「这个会话提到过这把钥匙」**，
  不等于「这个会话用这把钥匙发过请求」。
- **运行时取用**：只有经本保险库的调用会被记录。LLM 适配器在发请求时解析密钥的那一瞬间
  没有事件可以挂钩，所以那部分调用**不会**自动出现在访问记录里 —— 想要完整审计，
  就让消费方都改成 `vault get`（系统提示已经这么要求）。

扫描有预算上限（总字节数 + 时间），超出会截断并在 UI 上照常显示已扫到的部分，
不会假装扫全了。

## 删除即生效（墓碑）

删掉的凭据会留下一条墓碑记录：**即使它的来源（文件、`.env`、插件重写的配置）再次出现，
插件也不会把它当成活跃凭据**，只会以「已删除过」的形态藏在「显示已移出的」里，
要重新纳管必须显式点「恢复登记」。

删除前仍会自动留 `.bak-时间戳`，但那是给**你**回滚用的 —— agent 不会拿它自动复原。

## 安全边界

- 列表接口只下发掩码；明文只在 `reveal` 动作里下发，且需要浏览器同源信任栅栏通过。
- 秘密值不写日志、不进 URL、不进 `vault.json`。
- 明文配置项、只读环境变量都会被标出来提醒收归仓储。
- 文件型凭据的每次写入/删除都留 `.bak-时间戳`；`vault.json` 以 `0600` 落盘。
- 本插件不改变 DSH 的权限模型：它管理的是本机凭据，能读到 `~/.dsh` 的进程本来就能读到。
  它提供的是**可见性与统一入口**，不是进程隔离。

## 已知限制

- `.credentials.yaml` 的 `refs` 段用逐行解析取键名（不解析值），因为不想为它引入 YAML 依赖；
  目前 store 的写者只会写单行值，遇到多行块标量会漏掉那一条（值仍可从 store 正常解析）。
- 引用索引是全量扫描，第一次在几秒内完成；会话记录多时需要十几秒，期间页面显示上次结果。
- 会话扫描读取压缩记录，最多 24MB/文件、总预算 360MB；更大的会话会被跳过。
- **热重载后可能要在页面刷新一次**：Host 侧插件被热重载时，`clientModules` 的模块表有几率把本包的 client 行
  丢掉（重载瞬间 fiber 还没就绪的竞态），表现为设置页里暂时看不到「钥匙簿」。
  正常重启 DSH 时按 `bundles` 装配不会有这个问题（模块表在启动时统一组合）。
  真的遇到了：重启一次 DSH，或让注入器重新 reconcile 一次该包；仅刷新页面不够（模块表里没有这一行）。
